# 案例分享 CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `cases.html` / `case-detail.html` 改造成“案例分类 + 案例集合 + 自动生成列表/详情”的 CMS 结构。

> **范围更新（2026-11-08）**：案例汇总页 `/blog/` 与 `caseSettings` 已取消，只保留分类列表和案例详情。下文涉及汇总页的步骤按此执行。

**Architecture:** 新增 `caseCategories`、`cases`、`caseRedirects` 集合。`loadSiteData` 把集合组合成带模板标记的 `PageDoc`，复用现有静态生成管线输出 `/blog/`、分类分页和详情页；列表/详情由共享 React 视图渲染，不进入页面区块编辑器。

**Tech Stack:** Payload 3.90 / PostgreSQL、Next.js App Router、React 服务端渲染、原生 CSS Grid、Vitest、Playwright。

**Spec:** `docs/superpowers/specs/2026-11-03-case-cms-design.md`

## Global Constraints

- URL：`/blog/`、`/blog/page/{n}/`、`/blog/{categorySlug}/`、`/blog/{categorySlug}/page/{n}/`、`/blog/{categorySlug}/{caseSlug}/`。
- 分类没有草稿状态；分类下仍有案例时禁止删除分类。
- 案例必须填标题、slug、分类、封面、发布日期、富文本正文。
- 列表按 `publishedAt` 降序，同日期按 `createdAt` 降序。
- 列表卡片只显示封面 + 标题；详情只显示封面 Hero、标题、日期、富文本正文，无辅助导航。
- 列表默认每页 12 条，可被分类/汇总设置覆盖。
- 旧静态 URL `/cases.html`、`/case-detail.html?id=...` 不在本次实现范围。
- 不自动把分类插入导航；菜单编辑器可选择“案例汇总”或某个分类。
- 每次任务结束必须通过：`cd cms && npx tsc --noEmit && npx vitest run`。

## Review Focus

- 分页第 1 页不生成 `/page/1/`；最后一条删除后旧分页不应继续生成。
- 案例换分类或改 slug 后，旧详情 URL 必须可跳转，不能 404。
- 草稿阶段改 slug 不应产生重定向；链式改动合并为最终地址。
- 分类删除、分类下无案例、封面缺失时构建不能静默丢数据。
- 列表/详情在 390px 与 1280px 下无横向滚动，卡片标题可读。
- 菜单选择分类后链接必须解析为 `/blog/{slug}/`，详情页保持该菜单高亮。
