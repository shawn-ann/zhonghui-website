# 后台使用教程（Admin 内置）

日期：2026-11-14  
状态：设计待确认

## 1. 背景与目标

运营人员需要在后台完成菜单、页眉页脚、页面、文章和发布操作。当前只有开发向文档（`docs/content-components.md`、`docs/design-system.md`），不适合运营阅读。

目标：

- 在后台内提供一份随时可打开的图文教程；
- 按运营实际工作顺序组织：菜单 → 页眉页脚 → 页面 → 文章 → 发布；
- 每个操作场景用「一张大图 + 一组简短编号步骤」说明；
- 换页面时重新截图，不在同一张图上堆过多步骤；
- 内容可用 Markdown 维护，后台负责渲染成 HTML。

## 2. 非目标

- 不做视频教程；
- 不做全文搜索、评论、版本对比；
- 不允许运营在后台直接编辑教程内容（教程随代码发布）；
- 不做多语言版本；
- 不替换现有开发文档。

## 3. 方案选择

考虑过三种方式：

1. **纯 Markdown 文档**：开发成本最低，但运营需要额外链接，容易找不到，也无法从后台页面直接跳转。
2. **纯后台自定义页面（内容写在 TSX）**：运营体验最好，但长文维护困难。
3. **Markdown 作为内容源 + 后台页面渲染（选中）**：兼顾运营入口和维护效率。

选择方案 3。

## 4. 技术设计

### 4.1 路由与入口

- 新增 Payload 根级自定义视图：`/admin/tutorial`；
- 在 `payload.config.ts` 的 `admin.components.views` 注册 `tutorial`；
- 在 `AdminNav.tsx` 的「系统」组增加「使用教程」入口；
- 在页面列表、文章列表页头增加「查看教程」链接，分别跳到：
  - `/admin/tutorial#pages`
  - `/admin/tutorial#articles`
- 页面编辑器顶部操作栏可增加「教程」链接，跳到 `#pages`；
- 教程页内使用左侧章节导航 + 右侧正文，章节锚点可被外部链接直接打开。

### 4.2 鉴权

Payload 的自定义 admin view 默认可能被当作公开路由。教程视图必须在服务端校验登录：

- 使用 `payload.auth({ headers })`；
- 未登录时重定向到 `/admin/login?redirect=/admin/tutorial`；
- 不在教程页展示任何用户敏感信息。

### 4.3 内容源与渲染

- Markdown 源文件放在 **`cms/docs/user-guide/`**，确保 Docker 构建上下文（`cms/`）能包含；
- 文件固定顺序：
  - `01-menu.md`
  - `02-site-settings.md`
  - `03-pages.md`
  - `04-articles.md`
  - `05-publish.md`
- 服务端组件按顺序读取并拼接 Markdown；
- 使用 `marked` 渲染（当前 `node_modules` 已有该包，正式加入 `package.json` 依赖）；
- 为每个章节生成稳定锚点：`menu`、`site-settings`、`pages`、`articles`、`publish`；
- 图片引用 `/tutorial/<name>.png`，文件放在 `cms/public/tutorial/`。

### 4.4 页面结构

```text
/admin/tutorial
┌ 使用教程 ─────────────────────────────┐
│ 左侧章节导航        │ 右侧正文          │
│ 1. 配置网站菜单     │ 大图 + 编号步骤    │
│ 2. 配置页眉页脚     │                  │
│ 3. 配置页面         │                  │
│ 4. 文章配置         │                  │
│ 5. 站点发布         │                  │
└───────────────────────────────────────┘
```

- 复用后台现有 `zc-*` 设计令牌和卡片/标题样式；
- 正文最大宽度约 860–960px，截图自适应容器宽度；
- 小屏时左侧导航变为顶部折叠导航；
- 图片使用 `<figure>` + 简短说明，自适应正文宽度。

### 4.5 内容与截图规范

**截图环境（实现者决定）：**

- 使用本地 CMS：`http://admin.localhost:8080`，本地 Postgres 和现有 demo 数据；
- 使用本地测试账号 `admin@zhonghui.local`；
- 不在生产后台执行发布、删除等会产生真实影响的操作；
- 本地数据不足时，只允许在本地创建演示页面/文章，截图完成后可删除；
- 截图不出现真实用户、真实联系方式或敏感数据。

**文案分工（实现者决定）：**

- 由实现者根据实际界面编写 5 个章节的操作文案；
- 完成后交给需求方/运营审阅，按反馈修正；
- 不等待外部提供现成文案。

每章结构：

```markdown
## 配置网站菜单

一张覆盖当前页面主要操作区的截图。

1. 打开左侧「菜单」。
2. 点击「添加菜单项」。
3. 填写名称，选择链接类型。
4. 需要二级菜单时，在子菜单里继续添加。

![菜单配置](/tutorial/menu-01.png)
```

规则：

- 步骤用祈使句，直接写“点击 / 选择 / 填写”，不解释原理；
- 一张截图对应一个页面状态；切换页面必须重新截图；
- 同一页面内的连续操作可合并为 3–6 步；
- 截图统一 1440px 宽、中文界面、演示数据固定；
- 组件说明不逐组件开章，按「布局容器 / 内容组件」分组，用一张属性面板截图 + 列表说明；
- 「常用组件用途表」覆盖全部 17 个当前启用的业务组件，分组沿用 `docs/content-components.md`：
  - 布局容器 4 个：分栏、网格、横向滚动、纵向容器；
  - 内容组件 13 个：横幅、标题、图片、图文卡片、图标卡片、富文本、图集、轮播、信息列表、文本条目、交替图文、流程步骤、图标列表；
  - 每个组件只写一行用途，不逐个截图；`gridRow` / `gridCell` 属于网格内部结构，不单独列入运营表格；
- 页面章节必须单独说明：
  - 新建页面后先添加「分栏」；
  - 选中分栏后，在右侧属性面板添加子组件；
  - 右侧属性的字段分组、保存与预览；
  - 常用组件用途表。

### 4.6 五个章节的截图清单（初稿）

1. 菜单
   - 菜单编辑页整体
   - 添加/编辑菜单项弹层（如为独立界面）
2. 页眉页脚
   - 站点设置页整体
   - 页脚信息/二维码区域
3. 页面
   - 页面列表 + 新建入口
   - 页面编辑器三栏整体
   - 添加分栏
   - 分栏属性 + 添加子组件
   - 组件属性面板
   - 页面保存/预览
4. 文章
   - 分类管理列表 + 新建分类
   - 文章列表 + 新建文章
   - 文章编辑页字段与封面
   - 文章发布
5. 发布
   - 页面列表发布状态/按钮
   - 发布后侧栏重建状态
   - 前台访问结果

## 5. 维护方式

- 改教程：编辑 `cms/docs/user-guide/*.md`，替换 `cms/public/tutorial/*.png`；
- 需要重新构建并部署 CMS 后才生效；
- 后台界面改版后，优先更新对应章节截图和按钮名称。

## 6. 验收标准

- 登录后台后能从左侧导航打开 `/admin/tutorial`；
- 未登录访问教程会跳转登录页；
- 5 个章节顺序正确，锚点可直接打开；
- 每章至少一张截图，步骤编号连续、无多余解释；
- 页面章节完整说明「先分栏，再在右侧属性添加子组件」；
- 文章章节覆盖分类、文章必填项、封面和发布；
- 发布章节明确说明“发布后才能在前台访问”；
- 移动端可读，图片不溢出；
- 不新增数据库表，不影响现有页面/文章发布流程。

## 7. 留给实现者决定

- 教程页使用服务端组件直接读取 Markdown，还是构建时生成静态 HTML；
- 左侧导航是 sticky 还是普通文档流；
- 是否增加图片灯箱；
- 是否给截图加编号标记（如需要，优先用 DOM 注入标记后再截图，不手工修图）。
